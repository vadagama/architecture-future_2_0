# Расширенный технический радар — «Будущее 2.0»

Целевой технологический стек на горизонте 3 года. Включает технологии, платформы и архитектурные паттерны.

## Статусы

| Статус | Значение |
|---|---|
| **Adopt** | Рекомендовано к широкому применению. Проверено в бою, зрелая технология/паттерн |
| **Trial** | Активно исследуется в пилотных проектах. Есть положительный опыт, но ещё не стандарт |
| **Assess** | Стоит изучить. Потенциально полезно, но требует оценки в контексте «Будущего 2.0» |
| **Hold** | Не рекомендуется для новых проектов. Используется только в легаси, выводится из эксплуатации |

---

## Инфраструктура и облако

| Технология | Статус | Обоснование |
|---|---|---|
| **Yandex Cloud** | Adopt | Целевая облачная платформа. Managed-сервисы для Kafka, PostgreSQL, Object Storage, K8s |
| **Terraform** | Adopt | IaC для всех окружений. Модульная структура из Task 1 |
| **Minio (S3-совместимое)** | Adopt | Объектное хранилище для Data Lake и backend Terraform |
| **Docker / Kubernetes** | Adopt | Контейнеризация доменных сервисов. Yandex Managed K8s |
| **GitHub Actions** | Adopt | CI/CD пайплайны (Task 2) |
| **On-premise серверы** | Hold | Выводятся из эксплуатации. Остаются только для регуляторно-чувствительных данных на время аттестации облака |

## Данные и хранение

| Технология | Статус | Обоснование |
|---|---|---|
| **PostgreSQL** | Adopt | Основная OLTP-БД для доменов (медицина, финтех, фарма). Yandex Managed PostgreSQL |
| **TimescaleDB** | Adopt | Временные ряды для телеметрии оборудования |

## Интеграция и события

| Технология | Статус | Обоснование |
|---|---|---|
| **Apache Kafka** | Adopt | Центральная событийная шина. Yandex Managed Kafka |
| **Schema Registry (Avro)** | Adopt | Валидация и версионирование контрактов событий |
| **Kafka Streams / Kafka Connect** | Adopt | Потоковая обработка и коннекторы к источникам |

## Архитектурные паттерны

| Паттерн | Статус | Обоснование |
|---|---|---|
| **Data Mesh** | Adopt | Целевая архитектурная парадигма. Децентрализованное владение данными, Data Products |
| **Event-Driven Architecture** | Adopt | Основной способ интеграции доменов. Асинхронная публикация/подписка через Kafka |
| **Self-service BI** | Adopt | Бизнес-пользователи строят отчёты без участия IT. DataLens + каталог Data Products |
| **Domain-Driven Design (DDD)** | Adopt | Методология разделения на bounded contexts. Агрегаты, доменные события |
| **Anti-Corruption Layer (ACL)** | Adopt | Изоляция легаси-форматов. Legacy Bridge в целевой архитектуре |
| **Strangler Fig** | Adopt | Постепенный вывод легаси: перехват функциональности новым кодом |
| **CQRS** | Assess | Разделение команд и запросов. Потенциально для высоконагруженных доменов |
| **Event Sourcing** | Assess | Хранение состояния как последовательности событий. Оценка для финтех-домена (аудит) |
| **Outbox Pattern** | Adopt | Атомарная запись в БД + публикация события. Гарантия доставки |
| **API Gateway** | Adopt | Единая точка входа для синхронных запросов. Kong |
| **Infrastructure as Code (IaC)** | Adopt | Terraform для всей инфраструктуры |
| **GitOps** | Trial | Декларативное управление инфраструктурой через git. Оценка: ArgoCD для K8s |
